# Incident Research Checklist

- [ ] Find a primary-source report or postmortem.
- [ ] Confirm date and affected service.
- [ ] Separate verified facts from commentary.
- [ ] Note timeline and user impact.
- [ ] Distinguish trigger from contributing conditions.
- [ ] Understand detection, mitigation and recovery.
- [ ] Identify changes to testing, rollout, isolation or observability.
- [ ] Record what is not publicly known.
- [ ] Link every source used.

A useful postmortem explains the system conditions that allowed an incident and the actions that reduce recurrence. Avoid speculating about individual motives.
