# Open Source Learning: Four Weeks

## Week 1 — Observe
Choose a project you use, such as Kubernetes, OpenTelemetry or Prometheus. Read its contribution guide, code of conduct, issue labels, test instructions and release process.

## Week 2 — Reproduce
Choose a small documented issue or documentation gap. Follow setup instructions, reproduce it, and capture a minimal example. Search existing issues first.

## Week 3 — Contribute
Start with documentation, an example, a regression test or a small bug fix. Make one logical change, run relevant tests and explain how it was verified.

## Week 4 — Learn from review
Read feedback carefully, ask clear questions, update the change and record the project's conventions.

## Checklist
- [ ] Need or issue is clear.
- [ ] Change is focused.
- [ ] Tests or manual verification are described.
- [ ] Documentation updated if needed.
- [ ] No secrets or private logs included.
- [ ] I can explain every changed line.

Explore [Kubernetes contributors](https://www.kubernetes.dev/), [OpenTelemetry community](https://opentelemetry.io/community/), and [CNCF projects](https://www.cncf.io/projects/). Follow each project's current contribution instructions.
