# Engineering Growth Dashboard

## Goal
Become an engineer who reasons about systems, debugs with evidence, explains trade-offs, and builds reliable automation—not someone who only copies commands.

## Weekly rhythm
- Monday–Friday: 20 minutes (recall, study, explain/test, log next question).
- Saturday: 45–90 minute hands-on lab.
- Sunday: 15 minute review and next-week plan.
- Minimum viable day: explain one term or read one page.

## Learning loop
1. State a precise question.
2. Predict what will happen and why.
3. Read trusted documentation.
4. Run one small, reversible experiment.
5. Observe output, logs, metrics or traces.
6. Explain the result without copying.
7. Connect it to another system.

## First four weeks
1. DNS, IP, routing and TCP.
2. HTTP, TLS, certificates, proxies and load balancers.
3. Containers and Kubernetes networking.
4. Diagnose deliberate failures in a safe local lab.

Track artifacts: diagrams, notes, repeatable labs, explained concepts, useful runbooks. Use only systems you own or are authorized to test. Never put confidential work data into unapproved AI tools.
