# How to Learn Technical Topics Deeply

## Read in layers
1. Orientation: what problem does it solve, and what came before it?
2. Mental model: identify components, boundaries, inputs and outputs.
3. Happy path: trace one normal request end-to-end.
4. Failure path: learn symptoms and how to distinguish causes.
5. Hands-on: reproduce a small example.
6. Trade-offs: what does it simplify and what complexity does it add?
7. Retrieval: explain it tomorrow without notes.

## Use AI without outsourcing thinking
1. Try independently for 5–10 minutes.
2. State your hypothesis and ask for a hint.
3. Ask for explanations of unfamiliar lines and alternatives.
4. Verify commands, versions and APIs against official docs.
5. Test both success and failure paths.
6. Summarize the change without looking at the generated answer.
7. Reproduce the core idea later from a blank file.

## Debug systematically
State the symptom precisely; map the dependency path; gather evidence; find the earliest failing boundary; change one variable at a time; verify recovery; record what would detect recurrence.

Avoid passive tutorial consumption, blind command copying, changing several variables at once, treating logs as the only truth, or assuming AI is correct because it sounds confident.
