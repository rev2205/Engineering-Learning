# Classic Papers and Books

Read for ideas, not to collect titles. Start with abstract, introduction, figures, evaluation and conclusion; revisit details relevant to your questions.

## Foundational papers
- The Google File System (GFS): distributed storage, replication and failures.
- MapReduce: large-scale data processing abstraction.
- Bigtable: distributed structured storage and design trade-offs.
- Dynamo: availability, partitioning, replication and eventual consistency.
- Chubby: coordination and locking.
- In Search of an Understandable Consensus Algorithm (Raft): elections, log replication and consensus.
- Spanner: global distribution, time, replication and transactions.
- Large-scale cluster management at Google with Borg: scheduling and resource management.
- Omega: flexible schedulers for large compute clusters.
- Borg, Omega, and Kubernetes: evolution of cluster management.

Search for original papers from authors or institutions. Record year, problem, key idea, assumptions, evaluation and limitations.

## Book shortlist
1. **Code: The Hidden Language of Computer Hardware and Software — Charles Petzold.** Friendly foundation.
2. **The Phoenix Project — Gene Kim, Kevin Behr, George Spafford.** Fictional introduction to flow and DevOps.
3. **How Computers Really Work — Matthew Justice.** Visual tour of computer architecture.
4. **How Linux Works — Brian Ward.** Linux internals and system administration.
5. **The Unicorn Project — Gene Kim.** Developer experience and delivery constraints.
6. **The Secret Life of Programs — Jonathan E. Steinhart.** Visual computing concepts.
7. **The Design of Everyday Things — Don Norman.** Design and feedback.
8. **The Illustrated Network — Walter Goralski.** Detailed networking diagrams; check current edition and price.
9. **The Manga Guide to Databases.** Accessible relational database concepts.

Suggested starting pair: Code and The Phoenix Project. Choose How Linux Works for a Linux priority, or How Computers Really Work for a more visual approach.

## Paper worksheet
What problem mattered? What assumptions does the design make? What is the central mechanism? What evidence supports it? What are limitations? Which modern systems use related ideas?
